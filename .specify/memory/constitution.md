# Constitution — «УПС! Кулька»

Незмінні принципи проєкту. Spec Kit (`/speckit.*`) і всі агенти мають
перевіряти кожну специфікацію та план на відповідність цим статтям. Зміна
статті — лише через ADR у `docs/adr/`.

## I. Мобільний перший
Кожен екран спершу проектується для телефона (360–430 px). Покупець має
дійти від головної до товару за ≤ 3 тапи.

## II. Швидкість — це функція
Цілі на мобільному 4G: LCP < 2,0 с, INP < 200 мс, CLS < 0,05. Публічні
сторінки рендеряться на сервері. Зображення — лише AVIF/WebP потрібного розміру.

## III. SEO через підбірки
Підбірки (привід, для кого, колір, тема, ціна) — головний спосіб навігації і
трафіку. Індексуються лише підбірки з унікальним текстом і ≥ 6 товарами.

## IV. Чиста архітектура
Домен не залежить від фреймворків. Роутери тонкі, бізнес-логіка — у use cases
і домені, доступ до БД — через репозиторії й Unit of Work, залежності — через
DI-контейнер. Межі перевіряються автоматичними тестами.

## V. Тести обов'язкові
Кожна зміна поведінки має тест. Інтеграційні тести — лише на PostgreSQL.
Червоний CI блокує злиття.

## VI. База даних під контролем
Кожна зміна схеми супроводжується міграцією та перевіркою індексів. Кожен
новий запит перевірено на N+1 і, якщо він важкий, через EXPLAIN.

## VII. Контракт API — спершу
API описується Pydantic-схемами FastAPI, `contracts/openapi.json` комітиться,
фронтенд генерує клієнт із нього. Ламаючі зміни — лише з новою версією.

## VIII. Гроші й дані
Гроші — цілі копійки. Персональні дані клієнтів — мінімум і лише зі згоди.
Секрети — лише в змінних середовища.

## IX. Українська мова інтерфейсу
Усі тексти для покупців — українською, URL — латиницею (офіційна
транслітерація).
