# ADR 0001 — Чиста архітектура і модульний моноліт

Статус: прийнято, 2026-11-03

## Контекст
Магазин почнеться з однієї точки, але має рости (кілька точок, оплата,
програма лояльності). Код писатимуть люди й AI-агенти; без жорстких меж він
швидко перетвориться на «кому бруду» (big ball of mud).

## Рішення
- Один деплойний сервіс (модульний моноліт), поділений на модулі за бізнес-
  областями: `catalog`, `collections`, `orders`, `delivery`, `payments`, ...
- Кожен модуль має шари `domain / application / infrastructure / presentation`.
- Бізнес-логіка — у use cases і домені; роутери тонкі; БД — через репозиторії
  та Unit of Work.
- Межі перевіряються автоматичними тестами (`tests/architecture/`), а не лише
  код-рев'ю.

## Наслідки
+ Логіку легко тестувати без БД; агенти мають однозначні правила.
+ Модуль можна винести в окремий сервіс, якщо колись буде потрібно.
− Більше файлів і шаблонного коду для простих CRUD. Пом'якшення: для читання
  вітрини дозволено query-порти, що одразу повертають DTO.
