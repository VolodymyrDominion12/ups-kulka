# ADR 0003 — Контроль N+1 та індексів

Статус: прийнято, 2026-11-03

## Рішення
1. У всіх ORM-зв'язках `lazy="raise"`: випадкове ліниве завантаження одразу
   падає з помилкою, а не тихо робить N запитів.
2. Фікстура `query_counter` рахує SQL-запити; кожен інтеграційний тест на
   список перевіряє `assert_max_queries(n)` на малому й великому наборі даних —
   кількість запитів має бути однаковою.
3. Тест `test_foreign_keys_are_indexed` після застосування міграцій шукає в
   `pg_catalog` зовнішні ключі без індексу і падає, якщо такі є.
4. `alembic check` у CI гарантує, що ORM-моделі й міграції збігаються.
5. Для важких запитів — `EXPLAIN (ANALYZE, BUFFERS)` у PR (чек-лист AGENTS.md).
