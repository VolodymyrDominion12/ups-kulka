# 010 — Перенесення каталогу зі старого сайту

Статус: в роботі. Дані знято з https://oops.kylka.shop 2026-11-03.

## Навіщо
Новий магазин має стартувати з тим самим асортиментом, що й старий.

## Рішення власника (2026-11-03)
- Усі товари переносимо, включно з «Сучка» (старий id 224).
- Категорія «Для нього» лишається, навіть порожня: тег `dlia-noho` створюється
  завжди (порожні підбірки не видаляємо — див. технічний план).

## Що переносимо
- 211 товарів: назва, ціна, стара ціна (для акцій — пізніше), фото (URL на
  старому сайті — для 009-media), стара категорія.
- Назви перекладено українською й виправлено помилки (наприклад «Паравоз» →
  «Паровоз», «Доакоша» → «Дракоша»).
- Старі категорії → теги:

| Стара категорія | Тег (група / slug) |
| --- | --- |
| Для нього | recipient / `dlia-noho` |
| Для неї | recipient / `dlia-nei` |
| Для закоханих | occasion / `dlia-zakokhanykh` |
| Свята для дітей | occasion / `dytiachi-sviata` |
| Коробка | type / `korobka` |
| Фотозона | type / `fotozona` |
| Збери сам | type / `zbery-sam` |

## Критерії приймання
- Slug — офіційна транслітерація назви (постанова КМУ № 55 від 27.01.2010);
  однакові назви отримують суфікс зі старим id (`drakon-298`).
- Скрипт ідемпотентний: повторний запуск не створює дублікатів.
- Імпорт іде через use cases каталогу (`CreateTag`, `CreateProduct`), тож
  працюють ті самі перевірки, що й в адмінці.
- Порядок «новіші першими» такий самий, як на старому сайті.
- Акційна ціна старого сайту переноситься як стара (закреслена) ціна.
- Фото кожного товару проходить той самий конвеєр, що й фото з адмінки
  (009): 4:5, WebP кількох розмірів, розмитий плейсхолдер.
- Повторний запуск не дублює фото; товар, фото якого не вдалося перенести,
  лишається на вітрині з ілюстрацією і з'являється у звіті скрипта з причиною.
